用 HaS 模型做视频屏幕打码：五轮调参换来一个检到即打

2026 / 06 / 15
计算机视觉 YOLO 视频处理 隐私打码

第一人称录制的视频里，屏幕几乎无处不在。手里操作的手机、背景开着的 MacBook，上面可能有聊天记录、密码输入、账户信息。这是规则 7 要解决的事：检测视频帧里的屏幕，对屏幕区域打码。

检测器：腾讯玄武的 HaS

选型上我直接用了腾讯玄武实验室开源的 HaS（Hide-and-Seek），xuanwulab/HaS_Image_0209_FP32，MIT 协议，HuggingFace 上能直接拉。

技术上是 YOLO11 实例分割，ultralytics 原生加载，和项目里已有的 YOLO 栈完全一致。权重文件 sensitive_seg_best.pt，119MB，识别 21 类隐私对象。我需要的两类：

  • class 15 = mobile_screen（手机屏幕）
  • class 16 = monitor_screen（电脑显示器）

实例分割的好处是直接给像素级 mask，比矩形框精确得多。打码只盖屏幕显示区域，不会误伤手机边框或者显示器边框。其余 19 类（身份证、银行卡、护照、二维码等）以后做证件打码也能复用，先留着。

两段式管道

架构复用了人脸打码（gpu_deface.py）的双段式设计，只把检测器换掉：

  1. CPU 检测段：低频（3fps）跑 HaS，标出”有屏幕”的帧，合并成时间段 segments，输出 JSON
  2. GPU 打码段：对有屏幕的 segments 做分段重编码，每帧取 HaS mask 打马赛克，其余段无损 copy

这样 CPU 段只跑 3fps，不用全程高精度扫描。GPU 只处理有内容的片段，编码管道和人脸打码完全一致（闭合 GOP + 时间戳对齐拼接），接进生产 workflow 几乎零改动。

五轮调参

测试视频是 VID_20260615T074031_654Z.mp4，31 秒，1920×1440，办公室场景，手持手机加背景多台 MacBook。

轮次 问题 根因 解法
v1 深色主题屏幕漏打 mean_L≥40 亮屏判断把黑底白字屏误当息屏 降 mean_L 阈值到 15，靠 lap_var 判内容
v2 旁边电脑屏没识别 只启用了 class 15，没加显示器 加入 class 16（monitor_screen）
v3 背景远处小屏漏检 默认 imgsz=640，高分视频里的小屏被压糊了 --imgsz 1280，总检出 +37%
v4 低亮度手机屏仍漏打 亮屏阈值对低亮度真屏仍判”息屏” --no-active-filter，信任 HaS，检到即打
v5 电脑背板被当屏幕检出 conf=0.2 太低，引入大量低置信假阳性 --conf 0.70，滤掉背板

为什么扔掉亮屏判断

最初的需求是”只在屏幕有内容时打码”，用亮度（mean_L）和纹理（lap_var）来判断屏幕是不是亮着。听起来合理，实操起来是个陷阱。

深色主题（黑底白字）、系统深色模式、低亮度环境下，亮屏阈值会把真屏幕踢掉。五轮调参里有三轮都在和亮屏判断较劲，每次改参数都有一类场景被误杀。

调头看 HaS 的检测输出才发现：真屏幕（含低亮度手机屏）的置信度基本稳在 0.9 以上，根本不需要再用亮度来过一遍。--no-active-filter 直接信任模型，检到就打。代价是偶尔打到息屏的手机，隐私层面无害。

conf=0.70 这个数怎么来的

v5 发现电脑背板被当屏幕检出，根因是 conf=0.2 太松了。看了一遍各类检测的置信度分布之后发现：

  • 背板假阳性集中在 conf 0.2 到 0.65
  • 真屏幕（含低亮度手机）基本全在 0.9 以上

conf=0.70 卡在中间，两侧分得很清楚。这也说明 HaS 对屏幕的置信度分布两极化，不是那种在阈值附近飘的模型，用单一阈值就能干净切开。

小屏幕召回靠分辨率

高分视频（1920×1440）里，背景的 MacBook 屏幕在画面里很小。imgsz=640 推理时这些小屏被压到几个像素，检不到。提到 imgsz=1280 之后，总检出量增加了 37%，主要来自背景小屏。

推理变慢是代价，分辨率翻倍大约翻 4 倍时间，但 CPU 段只跑 3fps，可以接受。

遗留的两个坑

背景极远处的小屏，conf=0.70 下会漏。要覆盖这类目标需要 SAHI 切片推理，工程量不小。当前手机和近处显示器已经满足，背景远屏是否必须打是产品层面的决策。

“检到即打”会打到息屏手机，和最初”只打有内容屏”的需求有出入。若严格要求只打有内容的屏，应该走 OCR 路线（如 PP-OCRv6），检测文字而非屏幕物体，深色主题也能通吃。当前 HaS 召回够用，先留着。

几点收获

  1. 亮屏阈值这类手工规则比想象中脆，深色主题、低亮度、反光都能让它失效。不如直接信任模型的置信度，一个参数解决。
  2. 看置信度分布值得花时间。不同类别误检的 conf 范围往往不同，单一阈值经常能干净切开真假阳性，不需要多级规则。
  3. 高分视频里的小目标一定要提 imgsz，默认分辨率下根本进不了模型的感受野。
  4. 架构上复用已有管道（分段重编码、闭合 GOP、时间戳对齐）省了大量工作，前期把管道抽象好是值得的投入。
