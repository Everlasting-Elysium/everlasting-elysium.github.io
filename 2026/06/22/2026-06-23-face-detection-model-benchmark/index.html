WIDER FACE 高分不等于实战强：第一人称视频人脸检测模型评测

2026 / 06 / 23
计算机视觉 模型选型 YOLO 人脸检测 SCRFD WIDER FACE

项目里有一条质检规则：第一人称视频里必须有人脸才算有效。场景是 iPhone 拍的第一人称视频（1920×1440，30fps），人脸通常偏小、角度多变，漏检代价高。

听起来找个人脸检测模型跑上去就好了。结果一测，WIDER FACE 基准上得分高的模型，在这个场景里直接翻车。记录一下。

怎么测的

拿了 3 段有人脸的视频，从 COS 下载原视频（非打码版）。按 fps=2 抽帧，总共 1815 帧——273 帧有人脸，1542 帧无人脸。每帧在 eval-deck 面板里人工标注了 has_face / no_face，这是真值（GT）。

测试方式有个关键点：每个模型先用极低阈值跑一轮，保留完整 score 分布，再用 tune_threshold.py 在 [0,1] 区间扫描，找最优工作点。 如果直接用默认阈值跑，低于阈值的框会被丢掉，就没法做阈值寻优了。

运行环境：Apple M1，Python 3.9，CPU 推理。

候选模型

模型 来源 参数量 WIDER FACE Hard AP
YOLOv11n-face akanametov/yolo-face ~2.6M 81.0%
YuNet opencv/face_detection_yunet 75K 75.0%
SCRFD-2.5G (det_500m) insightface/buffalo_sc 0.67M 77.9%

WIDER FACE Hard AP 是业界主流的人脸检测基准，专测小脸和遮挡场景。按这个指标看，SCRFD-2.5G（77.9%）和 YOLOv11n-face（81.0%）只差了 3 个点，应该在同一个量级。

结果完全不是这回事。

结果：F1 差了将近一倍

模型 最优 conf Precision Recall F1 TP FP FN TN
YOLOv11n-face 0.3012 76.1% 97.1% 0.853 265 83 8 1459
SCRFD-2.5G@640 0.3327 42.2% 51.6% 0.465 141 193 132 1349
SCRFD-2.5G@320 0.0385 15.1% 100% 0.262 273 1538 0 4

YuNet 根本没进入寻优阶段：默认 score_threshold=0.3 下只检出了 185/1815 帧（10%），检出太少，扫阈值没意义。

YOLO 碾压。F1 0.853 vs SCRFD 0.465——WIDER FACE 上只差 3 点，实战差了将近一倍。

SCRFD 为什么翻车

意外的结果，值得挖一下原因。

参数量太小。 测的是 SCRFD-2.5G 里的 det_500m 版本，参数量只有 0.67M。这是 insightface 里面最轻量的一档，对小脸/侧脸场景能力有限。SCRFD-10G（WIDER FACE Hard 83%）和这个不是一回事，只是 CPU 单帧约 1.2 秒太慢，这次没条件测。

分辨率是决定性参数。 同一个模型，det_size=640 和 det_size=320 的 F1 是 0.465 vs 0.262，差距巨大。320 分辨率下精度直接崩，只有把阈值压到 0.0385 才能保住召回，代价是 1542 个负样本里误检了 1538 个——精度只剩 15.1%。

场景分布不同。 第一人称视角下，人脸通常从侧面、远距离、偏角度出现。WIDER FACE 的 Hard 档虽然有小脸和遮挡，但整体场景分布和第一人称 iPhone 视频不一样。benchmark 上的数字没法直接映射到这里。

YuNet 的问题

YuNet 速度最快（9ms/帧，是 YOLO 的 1/3），参数量只有 75K，很诱人。但检出率 10% 完全不可用。

YuNet 的设计定位是正脸、近距离的快速粗筛，比如自拍场景。第一人称视频里脸通常不在中心、不正对镜头，正好踩了它的软肋。速度快对这个场景没有意义。

YOLO 阈值寻优

默认 conf=0.5 不是最优工作点。扫描之后几个典型工作点：

目标 conf Precision Recall F1
默认 0.5 0.5000 100% 59.3% 0.706
F1 最优（生产推荐） 0.3012 76.1% 97.1% 0.853
召回=100% 0.0547 25.0% 100% 0.399

把 conf 从 0.5 降到 0.3012，F1 从 0.706 涨到 0.853，召回从 59.3% 涨到 97.1%。代价是精度从 100% 降到 76.1%，即 1815 帧里多了 83 个误检。

这个场景漏检（FN）的代价远大于误检（FP）：漏掉有人脸的帧会直接让质检误判视频无效。召回优先，conf=0.3012 是合理的生产工作点，已经写入 detectors.yaml。

速度对比

模型 总时间（1815 帧） 每帧
YuNet@320×240 17s 9ms
SCRFD-2.5G@640 86s 47ms
YOLOv11n-face@640 (lowconf) 74s 41ms
YOLOv11n-face@640 (conf=0.3012) 55s 30ms

YuNet 最快，但没有实用价值。YOLO 在 conf=0.3012 下约 30ms/帧，批量离线处理完全可接受。

几点收获

1. WIDER FACE AP 不等于实际场景效果。 SCRFD-2.5G 在 WIDER FACE Hard 上 77.9%，比 YOLO 只低 3 点，但实际 F1 差了 0.388。benchmark 和目标场景的分布不同，选型必须在真实场景上实测，不能只看论文数字。

2. 模型系列内部差异很大，搞清楚版本再测。 SCRFD 有多个子模型，det_500m 是最小的那档。如果有 GPU 条件，SCRFD-10G 结果可能完全不同。名字里都有 SCRFD，但能力差别很大。

3. 输入分辨率是敏感参数。 同一个模型 640 vs 320，F1 从 0.465 掉到 0.262，相当于基本不可用。换模型之前先确认输入分辨率够不够。

4. 低阈值预跑是阈值寻优的前提。 直接用默认阈值跑、看检出率是个思路陷阱。正确做法是用极低阈值跑一轮保留完整 score 分布，再做扫描寻优。

后续

SCRFD-10G（WIDER FACE Hard 83%）和 RetinaFace-MNetV2（Hard 86.6%，需 Python ≥3.10）还没测，两者都需要 GPU 环境。如果后续有 GPU 实验机，值得补上这两个对比。目前在 CPU 场景下，YOLOv11n-face conf=0.3012 是当前最优选。
