NudeNet v3 裸露检测打码：七轮踩坑，三个关键设计

2026 / 06 / 17
视频处理 隐私打码 目标检测 NudeNet

规则 8 要做的事：视频里出现低于”背心+短裤”着装标准的裸露部位时，检测并打码。听起来直接，实际上从可行性验证到打出合格效果，跑了七轮迭代。这篇记录完整踩坑过程，避免以后重蹈。

检测器：NudeNet v3

可选方案里，NudeNet v3（notAI-tech/NudeNet，AGPL-3.0）有个独特优势：18 个类别，每类都区分 EXPOSED 和 COVERED。

这正好实现”该遮的有没有遮”的着装合规逻辑，不需要额外写规则判断”这块被遮住了吗”，模型输出直接告诉你。技术上是 YOLOv8 ONNX，默认加载 320n（12MB），纯 CPU 50 到 150ms 每帧，pip install nudenet 自带。

需求确认结果：男性裸胸算超标（背心遮胸，光膀子就低于标准）；女性露腹、露肩不打（背心短裤本就露腹肩）。打码触发的六类：

性别误判存在，男胸常被标成 FEMALE_BREAST_EXPOSED，但不影响打码，两类都打。

七轮调参全记录

测试用两段视频：一段办公室视频（无裸露，验证误检率），一段含裸露视频（289 帧，验证召回）。

轮次 问题 根因 解法
1 可行性验证 — NudeNet 能检到女胸、男胸、裆、臀，召回合理（和纹身检测不同）
2 打码框太小，盖不全 NudeNet bbox 只框乳头等核心像素 box_expand 统一放大框
3 男性裸胸没打 初始只启用女性类 加入 MALE_BREAST_EXPOSED
4 打码薄、显色 马赛克保留肤色和轮廓（低频信息透出来） 改实心黑块（fill_mode=solid）
5 画面一闪一闪 320n 在 1fps 下连续裸露段间歇漏检 时间填充：漏检帧用最近邻检测帧的框补
6 横向放大太宽，波及周围 全局横向放大在成对检测时也扩 只对落单框横向加宽
7 第 3 秒缺了一半 NudeNet 完全漏检该帧（困难样本） 落单横向加宽缓解（非根治）

马赛克为什么不行

第 4 轮发现一个有点反直觉的问题：马赛克在裸露场景里效果很差。

马赛克是降采样再放大，会保留低频信息，肤色和大致轮廓透过来。隔着马赛克仍然能看出颜色和形状，对隐私保护来说不够用。

换成实心黑块（fill_mode=solid）之后，彻底不透，视觉上没有任何信息残留。这一改带来最大的感知改善，也是最值得记录的一点：遮挡类打码要用实心块，不要用马赛克。

落单框条件横向加宽

乳房是左右并排的。NudeNet 有时只检到一侧，另一侧漏了。简单解法是全局横向放大，但这样成对检测时也一起扩，太宽，影响旁边的区域。

解法：判断这个框在同一水平行（y 坐标有重叠）上有没有并排的伙伴。

  • 落单（只检到一侧）：横向大幅加宽（box_expand_x_lonely=5.0），覆盖漏检的另一半
  • 成对（左右都检到）：横向适度（box_expand_x=2.5），不影响周围

“缺一半”时补，”两个都有”时不过宽。这样在没有额外误检的情况下，落单漏检问题基本解决。

时间填充的三个版本

第 5 轮发现打码在时序上一闪一闪。320n 模型在 1fps 下连续裸露段会间歇漏检，漏检帧没打码，正常帧打了，来回切换就闪。

消除闪烁试了三个方案：

方案 效果
单帧最近邻：漏检帧用时间最近的检测帧的框补 稳定，不乱
前后框并集：漏检帧用前一帧和后一帧的框叠加 填充帧 2 框 vs 检测帧 1 框，大小跳变，产生新的闪动
滑动窗口并集：用滑动窗口内所有帧的框堆叠 7 帧的框全堆一起，乱打多层，比原来更差

只有第一版对。原因在于：框的数量和大小在相邻帧之间跳变，本身就是新的抖动来源。最近邻填充让漏检帧和最近的成功检测帧用完全一样的框，不会引入跳变。

教训：时序稳定不能靠”堆叠框”，越聪明的方案越容易引入新问题，单帧最近邻最稳。

最终配置

conf=0.20 是召回优先，宁可多打。temporal_gap=3 表示最多用相邻 3 帧的检测结果填充漏检帧。全部参数通过 CLI 可调：--conf/--box-expand-x/--box-expand-x-lonely/--fill-mode/--temporal-gap。

能力边界在哪里

第 7 轮缓解的那个第 3 秒困难样本没根治，要说清楚这是检测能力边界，不是代码问题。

那个场景叠了五个不利因素：隔玻璃窗、侧后方角度、远距离、暗光、玻璃反光。NudeNet 完全漏检，靠相邻帧借框填充，位置偏，横向加宽缓解，不能根治。

要从根本上提升这类漏检，最直接的路径是换更大的模型：NudeNet 640m（98MB），精度更高，对困难样本召回更好。官方 GitHub release 有重定向到登录页的问题，HuggingFace 上有镜像（SimonJoz/nudenet、zhangsongbo365/nudenet_onnx），--model 640m.onnx 加载即可。

另一个生产上更稳的思路是段级保守打码：检测到裸露时间段后，整段都打，困难帧靠段内其他帧带进去，单帧逐帧判断本来就不稳。

最后，NudeNet 是 AGPL-3.0，商用或分发需要法务过一遍。商用友好的替代是 EraX-Anti-NSFW（Apache-2.0），但没有 EXPOSED/COVERED 区分，着装合规这个语义精度差一级。

几点收获

  1. 遮挡类打码要用实心块，不要用马赛克。马赛克保留低频信息（肤色、轮廓），实心块才是真正不透。
  2. 时序稳定靠”简单”，堆叠框只会引入跳变。单帧最近邻填充，框不变、位置不变，视觉上最稳。
  3. 有并排语义的目标（左右乳房）需要单独处理”落单”情况，全局放大会误伤旁边区域。
  4. 困难样本（多个不利因素叠加）是模型能力边界，工程上的兜底是段级打码，不是在单帧检测上死磕。
